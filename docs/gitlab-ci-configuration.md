# GitLab CI/CD Pipeline Configuration Guide

**Project:** Snigdha OS Decentralized  
**Repository:** `https://gitlab.com/SnigdhaOS/decentralize/iso`  
**Pipeline File:** `.gitlab-ci.yml`  
**Stage:** `release-mirror`  

---

## 1. Overview

The GitLab CI/CD pipeline triggers automated release mirroring immediately after a release candidate or stable release is published on GitLab.

This pipeline integration ensures that release artifacts generated by mkarchiso and signed by the build environment automatically flow to the GitHub mirror without manual intervention.

---

## 2. Pipeline Stage Definition

In `.gitlab-ci.yml`, the `release-mirror` stage is added immediately after `release`:

```yaml
stages:
  - lint
  - test
  - security
  - build
  - verify
  - supply-chain
  - release
  - release-mirror
```

---

## 3. Dedicated CI Job Specification

The dedicated CI job `mirror:github` runs under the `release-mirror` stage.

```yaml
# =============================================================================
# Stage 8: Automated GitLab -> GitHub Release Mirroring (Tags Only)
# =============================================================================

mirror:github:
  stage: release-mirror
  image: python:3.11-slim
  rules:
    # Trigger ONLY for valid release tags (e.g. v2026.11.13 or v2026.11.13-rc1)
    - if: '$CI_COMMIT_TAG =~ /^v/'
  needs:
    - job: release:publish
      artifacts: false
  variables:
    GITHUB_RELEASE_REPOSITORY: "eshanized/org.snigdhaos.decentralize"
    GITLAB_RELEASE_PROJECT: "${CI_PROJECT_PATH}"
    TRUSTED_SIGNING_KEY_FINGERPRINT: "2BDB00AE6CABEF0E40520A8F553FD42B02A8211A"
  before_script:
    - apt-get update && apt-get install -y --no-install-recommends gnupg git curl ca-certificates
    - pip install --upgrade pip
    - pip install git+https://github.com/eshanized/org.snigdhaos.decentralize.git@master
  script:
    - echo "Synchronizing release ${CI_COMMIT_TAG} to GitHub mirror ${GITHUB_RELEASE_REPOSITORY}..."
    - release-mirror sync --tag "${CI_COMMIT_TAG}"
    - echo "Refreshing download analytics and public badges..."
    - release-mirror stats
```

## 4. Required CI/CD Variables

Configure the following variables in GitLab under **Settings > CI/CD > Variables**:

| Variable Name | Type | Flags | Description |
| :--- | :--- | :--- | :--- |
| `GITHUB_RELEASE_TOKEN` | Variable | Masked, Protected | GitHub Personal Access Token (PAT) with `repo` or Contents write scope. |
| `GITHUB_RELEASE_REPOSITORY` | Variable | Expanded | Target GitHub repository (default: `eshanized/org.snigdhaos.decentralize`). |
| `TRUSTED_SIGNING_KEY_FINGERPRINT` | Variable | Expanded | Canonical OpenPGP fingerprint (`2BDB00AE6CABEF0E40520A8F553FD42B02A8211A`). |
| `GITLAB_RELEASE_TOKEN` | Variable | Masked | *(Optional)* Access token for private/internal GitLab APIs; defaults to public unauthenticated access or `CI_JOB_TOKEN`. |

> [!IMPORTANT]
> Ensure `GITHUB_RELEASE_TOKEN` is set as **Masked** and **Protected** so it is never printed in CI logs or exposed on unapproved feature branches.

---

## 5. Execution Triggers and Branch Restrictions

The mirroring job enforces strict triggering conditions:
1. **Tags Only:** The job matches `$CI_COMMIT_TAG =~ /^v/` and will never run on branch pushes, draft pull requests, or ordinary commits.
2. **Sequential Dependency:** The job declares `needs: [release:publish]`, ensuring it only begins after the GitLab release has been successfully created and attached to the project.
3. **CalVer Support:** Automatically distinguishes stable releases (`vYYYY.MM.DD`) from release candidates (`vYYYY.MM.DD-rcN`), setting GitHub prerelease flags accordingly.
